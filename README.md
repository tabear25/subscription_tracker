# これは何（What's this?）

Notionで管理しているサブスクリプションの支払い情報を取得し、**Googleカレンダー / LINE へのリマインド通知**と**次回支払日の自動更新**を行うGoogle Apps Script (GAS) 製のツールです。

# 機能（Features）

* **事前通知**: 支払日の指定日前（デフォルトは7日前）に、Googleカレンダーに予定として通知を作成します。
* **LINE通知**（任意）: LINE公式アカウントを設定すると、以下をLINEにも届けます。
  * **支払予告**: 上記の「支払日7日前」通知をLINEにも配信します。
  * **月末の見直しリマインド**: 毎月末日に「先月、新規でサブスクを登録したり料金プランを変更したりしていませんか？」という確認メッセージを、現在の契約状況サマリー（契約中の件数・月額/年額換算合計・未使用候補）付きで送ります。
* **日付の自動更新**: 支払日が過ぎると、支払サイクルに合わせてNotion上の「次回支払日」を自動で書き換えます。
  * 現在、**毎月（Monthly）/ 3ヶ月ごと（Quarterly・Every 3 months・3 months）/ 年（Yearly）/ 2年（2 years）** に対応しています。
  * 月末払い（29〜31日）は、その日が無い月は月末日にそろえます（例: 1/31 → 2/28）。
* **値上げ検知**（任意）: 「価格監視」をONにしたサービスについて、登録した `URL` のページを**月1回**自動取得し、登録料金と一致する金額が見つからない場合に「値上げ・プラン変更の可能性」をLINEで通知します。※JavaScriptで描画されるページは金額を取得できないことがあり、その場合は手動確認を促すメッセージを送ります（ベストエフォート）。
* **未使用サブスク検知**: 「最終利用日」が一定日数（デフォルト60日）以上前の契約を、月末リマインドで「解約候補」として一覧表示します。利用日はLINEで「サービス名 使った」と送ると記録できます。
* **LINEで話しかけて確認・操作（双方向）**（任意）: GASをウェブアプリとしてデプロイすると、LINEのトークにふつうの文章で送るだけで使えます。詳細は [docs/LINE_WEBHOOK_SETUP.md](docs/LINE_WEBHOOK_SETUP.md)。
  * **支払日をいつでも確認**: 「Netflixっていつ支払いだっけ？」「今月の支払い」「来月いくら？」に、次回支払日・あと何日・金額で即答します（通知を待つ必要なし）。
  * **解約したい**: 「Netflix解約したい」で、**解約方法（解約ページのリンク・手順）と期限の目安（次回支払日の2日前まで。「更新の24〜48時間前まで」が締切のサービスがあるため）**を返します。手続き後に「解約した」と送るとNotionを `Canceled` にして通知を止めます。
  * **再契約したい**: 「Netflix再契約したい」で再契約ページと次回支払日の目安を返し、「再契約した」でNotionを `Active` に戻して次回支払日をセットします。
  * **解約し忘れ防止**: 「解約したい」と言ったまま完了の連絡がないと、支払日の**3日前と前日**にLINEで念押しします。
  * サービス名は一部（「disney」）や呼び名（「ネトフリ」「アマプラ」）、Notionの「別名」でもOK。名前を省いた「これいつ？」「解約した」は、直前に話したサービス（または当日の通知）として扱います。
  * 通知や返信には、タップで送れるボタン（「解約したい」「支払い予定」など）が付きます。
* **ステータス管理**: ステータスが `Active` なものだけを監視し、解約済みサービスの通知は行いません。

> ℹ️ **解約そのものの代行はできません。** Netflix などの各サービスは、外部から契約を解除・再開するための公開APIを提供していないためです（ログイン情報を預かって自動操作する方式は、規約・セキュリティ上のリスクが大きいため採用していません）。代わりに「解約ページへの1タップ誘導」「期限の提示」「完了の記録」「し忘れのリマインド」で、できるだけその状態に近づけています。

# 使い方（How to Use）

### 1. 準備（Preparation）

1. **Notionでデータベース（=DB）を作成する**
* Notion上でサブスク管理用のDBを作成（または既存DBを使用）してください。
* **プロパティ名（列名）と種類**は以下の通りに設定してください。
* ※コード内の定数を変更すればカスタマイズ可能ですが、デフォルトはこの設定です。


| プロパティ名 | 種類 (Type) | 備考 |
| --- | --- | --- |
| Name | Title | サービス名 |
| 更新日 | Date | 次回の支払日 |
| 料金 | Number | 金額 |
| Billing | Select | `Monthly`, `Quarterly`（`Every 3 months` / `3 months` でも可）, `Yearly`, `2 years` のいずれかを選択 |
| Status | Select | `Active` (契約中) を選択。LINEからの解約で `Canceled` が入ります |

**追加機能を使う場合のプロパティ（任意・無くても基本機能は動作します）**

| プロパティ名 | 種類 (Type) | 用途 |
| --- | --- | --- |
| URL | URL | サービスのアカウント（契約管理）ページ。値上げ検知のチェック先、解約・再契約リンクの予備としても使います |
| 価格監視 | Checkbox | ONにしたサービスだけ値上げ検知（月1チェック）の対象になります |
| 料金確認日 | Date | 値上げ検知が最後にチェックした日（ツールが自動更新。手動入力不要） |
| 最終利用日 | Date | 最後に使った日。未使用検知に使用。LINEの「使った」で自動更新されます |
| 解約用URL | URL | LINEで「解約したい」と送ったときに案内する解約ページ（最優先で表示） |
| 再契約URL | URL | LINEで「再契約したい」と送ったときに案内する申し込みページ（最優先で表示） |
| 解約方法 | Text | 解約の手順メモ（例:「受付で退会届。前月10日まで」）。LINEの解約案内に表示 |
| 支払方法 | Select（またはText） | `App Store` / `Google Play` / `docomo` など。App Store・Google Play・キャリア経由の課金は**サービスのサイトでは解約できない**ため、案内をそちらの手順に切り替えます |
| 別名 | Text | LINEで呼ぶときの名前（カンマ区切り。例: `ネトフリ, ネットフリックス`） |

> 列名はコード冒頭の定数（`PROP_URL` など）で変更できます。3ヶ月ごとの契約は、NotionのBillingセレクトに `Quarterly`（または `Every 3 months` / `3 months`）の選択肢を追加してください。
>
> 「解約用URL」「再契約URL」が空でも、主要サービス（Netflix / YouTube Premium / Spotify / Amazonプライム / Kindle Unlimited / U-NEXT / Disney+ / ChatGPT / Claude / Adobe / Microsoft 365 / Apple系）は組み込みの解約ページ・手順を案内し、それ以外はGoogle検索のリンクを返します。サービス側のURLは変わることがあるので、確実にしたいものはNotionに書いておくのがおすすめです。

2. **Notion API（無料）を取得する**
* [Notion My Integrations](https://www.notion.so/my-integrations)から新しいインテグレーションを作成し、`Internal Integration Secret`（トークン）を控えてください。
* 作成したインテグレーションを、1で作成したNotionデータベースのページに追加（コネクト）してください。

3. **DBID（無料）を取得する**
* 1で作成したDBのID（=DBID）を取得します。
* DBをフルページで開いた際のURLの以下の部分です。


```
https://www.notion.so/<データベースID>?v=<ビューID>
```

### 2. スクリプトの設置（Setup Script）

1. [Google Apps Script](https://script.google.com/) にアクセスし、「新しいプロジェクト」を作成します。
2. エディタに本リポジトリのコードをコピペします。
   - `main.js`: 本番のコード
   - `test.js`: 挙動確認用のコード
   - `webhook.js`: LINEで話しかけて確認・操作する場合のみ（[docs/LINE_WEBHOOK_SETUP.md](docs/LINE_WEBHOOK_SETUP.md)）
   - ※ `dev/` フォルダは開発用（Node.jsでのテスト）なので、GASには貼り付けません。

### 3. 環境変数の設定（Environment Variables）

GASの「スクリプトプロパティ」機能を使用します。

1. GASエディタの左メニュー「⚙️（プロジェクトの設定）」を開きます。
2. 最下部の「スクリプト プロパティ」に以下を追加してください。

| プロパティ (Key) | 値 (Value) |
| --- | --- |
| `NOTION_TOKEN` | 手順1-2で取得したトークン |
| `DATABASE_ID` | 手順1-3で取得したDBID |
| `LINE_CHANNEL_ACCESS_TOKEN` | （任意）LINE通知を使う場合のみ。後述の「LINE通知の設定」で取得 |
| `ALLOWED_LINE_USER_IDS` | （任意）LINEで操作（双方向）を使う場合のみ。許可する自分のユーザーID。[docs/LINE_WEBHOOK_SETUP.md](docs/LINE_WEBHOOK_SETUP.md) 参照 |

### 4. トリガーの設定（Set Trigger）

毎日自動でチェックするために、トリガーを設定します。

1. GASエディタの左メニュー「⏰（トリガー）」を開きます。
2. 右下の「トリガーを追加」をクリックし、以下のように設定します。
* **実行する関数**: `main`
* **イベントのソース**: `時間主導型`
* **タイプ**: `日付ベースのタイマー`
* **時刻**: `午前 8時 〜 9時` （通知を受け取りたい時間帯なので任意）

> **📌 通知の発火頻度（1日に何回通知するか）は、このリポジトリのコードではなく GAS の「トリガー」で制御しています。**
>
> `main` を実行するトリガーの**数と時刻**が、そのまま通知の回数・タイミングになります。
> 例）朝と夜に受け取りたい → `main` のトリガーを2つ（例: 午前8〜9時／午後7〜8時）作成すると1日2回になります。
> 逆に**1日1回に減らしたい**場合は、GASの「⏰（トリガー）」画面で余分な `main` トリガーを削除してください。
> **変更したいときは、コードを編集せず、GASの「⏰（トリガー）」画面で `main` トリガーを追加・削除・編集します。**
>
> （補足）`NOTIFY_DAYS_BEFORE`（`main.js`）は「支払日の何日前に予告するか」を決める設定であり、1日あたりの通知**回数**とは別物です。

## LINE通知の設定（任意 / LINE Notification Setup）

> **重要**: かつて定番だった **LINE Notify は 2025年3月31日にサービス終了**しました。本ツールでは現行の **LINE Messaging API（LINE公式アカウント経由のプッシュ配信）** を使用します。

> 📘 **初めての方へ**: [docs/LINE_SETUP.md](docs/LINE_SETUP.md) に、公式アカウントの作成からトークン発行・GASへの登録・テスト送信までの作業手順（所要15〜20分）を、つまずきやすいポイントやエラー対処付きでまとめています。

### 仕組み

GASから [Messaging API の broadcast エンドポイント](https://api.line.me/v2/bot/message/broadcast) を呼び出し、**公式アカウントを友だち追加しているユーザー全員**にメッセージを配信します。個人利用（自分1人だけが友だち）であれば、宛先のユーザーIDを調べる必要がなく最も簡単です。

`LINE_CHANNEL_ACCESS_TOKEN` を設定しない場合、LINE送信は自動的にスキップされ、カレンダー通知だけが動作します。

### 設定手順

1. **LINE公式アカウントを作成する**
   * [LINE Official Account Manager](https://manager.line.biz/) でアカウントを作成します（無料）。
2. **Messaging API を有効化する**
   * [LINE Developers Console](https://developers.line.biz/) で、作成した公式アカウントの **Messaging API チャネル**を有効化します。
3. **チャネルアクセストークン（長期）を発行する**
   * チャネルの「Messaging API設定」タブから **チャネルアクセストークン（長期）** を発行し、控えておきます。
4. **自分のスマホで公式アカウントを友だち追加する**
   * 同じく「Messaging API設定」タブのQRコードから、自分のLINEで**友だち追加**します（broadcastの配信先になります）。
5. **GASのスクリプトプロパティに登録する**
   * 手順3で取得した値を `LINE_CHANNEL_ACCESS_TOKEN` としてスクリプトプロパティに追加します。
6. **疎通テスト**
   * GASエディタで `testLineNotification` を実行し、自分のLINEに「【テスト】…」のメッセージが届けば成功です。

### 補足（Notes）

* **送信日（月末リマインド）**: 毎日実行される `main` トリガーの中で「今日が月末日か」を判定して送信します。**月次リマインドのために新しいトリガーを追加する必要はありません**（28/29/30/31日を月によらず正しく判定します）。タイムゾーンはGASプロジェクトの設定（`Asia/Tokyo` 推奨）に従います。
* **無料枠**: Messaging API は送信メッセージ数が**月200通**を超えると有料です。個人利用の通知頻度であれば通常は無料枠で十分です。なお、LINEで話しかけたときの**返信（reply）は通数にカウントされない**ため、「いつ支払い？」などの問い合わせは何回しても無料です（カウントされるのは通知などのbroadcastのみ）。

### LINEセットアップを Claude Code に手伝ってもらうためのプロンプト例

LINE Developers Console などの**GUI操作は自動化できません**が、検証や補助コードの生成は Claude Code に依頼できます。以下はそのまま貼り付けて使えるプロンプト案です。

* 「`LINE_CHANNEL_ACCESS_TOKEN` を使って broadcast でテスト1通を送る `curl` コマンドを作って」
* 「発行したチャネルアクセストークンが有効か疎通確認するワンショットスクリプトを書いて」
* 「`testLineNotification` をGASで実行する手順を、初めての人向けに教えて」
* 「毎月末日にだけリマインドが飛ぶか、`isLastDayOfMonth` のロジックを各月（1月〜12月、うるう年含む）でテストするコードを書いて」
* 「月額換算合計の計算（Monthly / Yearly / 2 years）が正しいか確認するテストを書いて」

### 注意点（Notes）

* **初回データの入力**: 導入時、Notionの「更新日」には**正確な次回支払日**を入力してください。ここが間違っていると通知もズレます。
* **解約時の運用**: サブスクを解約した場合は、Notionの `Status` を `Active` 以外（例: `Canceled`）に変更するか、日付を空欄にしてください。LINE連携を使っている場合は、LINEで「サービス名 解約した」と送れば自動で `Canceled` になります。
* **通知タイミング**: デフォルトでは「7日前」にGoogleカレンダーに登録されます。変更したい場合はコード内の `NOTIFY_DAYS_BEFORE` の数値を変更してください。
* **月末払いのずれ**: 31日払いなどは、短い月で月末日（2/28など）に寄せたあと、その日付を基準に次の月を計算します（例: 1/31 → 2/28 → 3/28）。実際の請求日と違ってきたら、Notionの「更新日」を直してください（前倒しにずれるので、通知が遅れることはありません）。

## 開発者向け: ローカルでのテスト（任意）

Node.js があれば、GASに貼らずにロジックと会話の流れを確認できます（外部への通信はしません）。

```bash
node dev/run-tests.cjs
```

`test.js` の `testLogic()`（GASエディタでも実行できる単体テスト）に加えて、LINEでの会話（「いつ支払い？」「解約したい」→「解約した」など）と、毎日の `main()`（請求予告・解約リマインド）を、Notion・LINEの偽物を使って検証します。
